# Agent and search limits

Agent steps and web searches are separate per-account settings. `maxSteps` defaults to 20 (range 1–50); `maxSearches` defaults to 5 (range 0–50). Existing accounts gain the search default without changing their saved agent limit. The settings API rejects non-integers, out-of-range values, strings, and null. Invalid legacy values fall back to defaults on read.

One agent step is one model invocation allowed to call tools, which may make multiple tool calls. Once the allowance is consumed, one final model invocation with `toolChoice: "none"` produces the answer; it cannot restart the tool loop. Counting agent steps alone therefore cannot constrain searching. `SearchBudget` reserves one query synchronously before a built-in `web_search` starts its first network request. Parallel tool calls and delegated tasks share the same budget. Failed queries consume a reservation; transport fallbacks within a query do not consume extra reservations. `web_fetch` page reading remains available at a zero or exhausted search budget. This cap applies to the built-in search tool, not arbitrary tools installed through MCP.

`turnStream` must construct one budget and pass it to both its `webTools` and `subagentTools`. The tool list stays constant so the provider prefix cache holds; an exhausted budget makes `web_search` return an error instead of hiding the tool. Sub-agents keep their existing maximum of 15 tool-capable agent steps, further constrained by the account's setting, plus a final response with `toolChoice: "none"` (tools stay listed for the cache).

Browser-executed tools can continue a reply in a new chat request. `searchesInCurrentTurn` recovers search calls after the latest user message, including delegated searches recorded in the sub-agent progress output, so the continuation does not reset its search allowance. `agentStepsInCurrentTurn` counts assistant `step-start` parts across those continuations, so approval responses and browser tools cannot restart the agent-step allowance either. A new user message starts fresh allowances. Scheduled prompts use the same turn machinery.

Validation: `src/server/settings.test.ts` covers account isolation, legacy defaults, validation, and invalid saved values. `src/server/tools/search-budget.test.ts` exercises actual tool execution against a fake transport, including parallel parent/delegated searches, failure consumption, zero limits, and continuation recovery.
