# Internationalization

The web UI is ready for translation. English is the only language shipped. Every user-facing string in `src/web` comes from a message catalog, and numbers, dates, and lists are formatted for the active locale.

## Pieces

| File | Role |
| --- | --- |
| `src/web/i18n/index.ts` | `t()`, plural selection, locale matching, `loadLocale`/`applyLocale`/`setLocale`, the `Translation` type |
| `src/web/i18n/en/*.ts` | The English source catalog, one namespace per area, collected in `en/index.ts` |
| `src/web/i18n/format.ts` | `formatNumber`, `formatPercent`, `formatDate`, `formatDateTime`, `formatTime`, `formatRelativeTime`, `formatList`, `compareText`, `formatBytes`, `formatTokens`, `formatCost`, `formatDuration` |
| `src/web/i18n/react.tsx` | `<Trans>` for text with elements inside |
| `src/web/i18n/locales.ts` | Finds `locales/<tag>.ts` translations with `import.meta.glob`; each is its own chunk |
| `src/web/i18n/i18n.test.ts` | Lookup, plurals, fallback, formatters, catalog shape, literal key usage, translation validity |

No dependency: lookup is about 150 lines on top of `Intl`. The English catalog (about 1,700 entries, 25 KB gzipped) is part of the startup bundle.

## Using it

```ts
import { t } from "@/i18n";
import { formatDate } from "@/i18n/format";
import { Trans } from "@/i18n/react";

t("common.cancel");
t("shell.tabTitle", { title });                     // placeholder required
t("sidebar.selectedCount", { count });              // plural entry, `count` required
formatDate(item.createdAt);                         // "Oct 30, 2026" in English
<Trans k="schedules.lastRunError" params={{ date, error: <span className="text-error">{message}</span> }} />
```

Keys are `namespace.key`, typed from the English catalog: a wrong key, a missing placeholder, or a plural entry without `count` fails `npm run typecheck`.

### Catalog rules

- One namespace per area (`thread`, `sidebar`, `memory`, ...). `common` holds words used in many areas (Cancel, Save, Delete). Area text stays in its area even when the English word repeats, because other languages may need a different word in a different context.
- Entries are a string, or plural forms `{ one: "{count} chat", other: "{count} chats" }` (`other` is required; translations use their own `Intl.PluralRules` categories). `{name}` placeholders take strings or numbers; numbers are formatted for the locale. Unknown `{name}` tokens stay literal.
- Keys are camelCase words without dots.
- Lookup tables of keys are typed `PlainMessageKey` (keys without params), e.g. `as const satisfies Record<Kind, PlainMessageKey>`, so `t(TABLE[kind])` compiles. A variable typed as the full `MessageKey` union cannot be passed to `t()`.
- Write whole sentences with placeholders. Never build a sentence by concatenating translated pieces or by adding `"s"` for plurals: word order and agreement differ between languages.
- Use keys literally (`t("memory.title")`). No computed keys such as `` t(`settings.${id}`) ``: map ids to literal keys instead. The test fails on catalog keys that appear nowhere literally, which also catches dead text.
- Never call `t()` at module top level. Modules evaluate before `loadLocale` resolves. Store the `MessageKey` in constants (`labelKey: "keyboard.newChat"`) and call `t()` when rendering, or wrap the text in a function.

### What is not translated

- Text sent to models (tool descriptions, system prompts in `src/server/prompts.ts`), stored data (chat titles, memory content), and log output.
- Proper names: product and provider names, theme names, font families, model ids, language names in code blocks.
- Server error messages. They reach the UI through `ApiError.message` and stay English until the server sends codes; `src/server` has no catalog.
- Keyboard key names come from `keyboard/keys.ts` and follow platform conventions.

## Locale selection

`main.tsx` calls `loadLocale(localeLoaders)` before the first render. It picks the stored choice (`localStorage["okaychat:locale"]`), then `navigator.languages`, matched by exact tag and then by language subtag, falling back to `en`. It loads that translation chunk and sets `<html lang>` and `dir` (right-to-left languages get `dir="rtl"`). English needs no chunk, so it renders without waiting.

The locale is fixed for the page's lifetime. `setLocale(tag | null)` stores the choice and reloads. There is no language picker yet because only English exists; add one to General settings with the first translation, listing `Object.keys(localeLoaders)` with `Intl.DisplayNames`. If the choice should follow the account across devices, store it in `user_settings` and mirror it to local storage, because `loadLocale` runs before any API call.

## Adding a language

1. Create `src/web/i18n/locales/<tag>.ts` exporting `default` a `Translation` (`import type { Translation } from "../index"`). Any subset of keys is valid; missing keys fall back to English, including English plural rules.
2. Use the language's plural categories (`Intl.PluralRules(tag).resolvedOptions().pluralCategories`).
3. Run `npm test`: the test rejects unknown keys and placeholders that the English entry does not have.
4. Add the language picker (see above) with the first translation.

Layout should already tolerate longer text. With the first right-to-left language, check directional Tailwind classes (`ml-*`, `left-*`, `text-left`), which do not flip; logical ones (`ms-*`, `start-*`, `text-start`) do.
