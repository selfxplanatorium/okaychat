# AGENTS.md

Guide for any agent (human or AI) working in this repo.

**Keep this file current.** When you change the stack, add a module, learn a non-obvious fact, or make a decision that the code alone does not explain, update this file (or the relevant doc under `docs/`) in the same change. Stale guidance is worse than none.

## What this is

okaychat is a self-hosted AI chat app meant to replace LibreChat and Open WebUI. Goals: polished UI, every provider, OpenCode Go as the primary connection, MCP that just works, good prompt-cache behavior, usage and context tracking, and compaction.

- Self-hosted, Docker, multi-user capable (each user has their own keys, MCP servers, and settings).
- Lightweight stack. Avoid adding heavy dependencies without a reason written down here.

## Stack

| Layer | Choice | Why |
| --- | --- | --- |
| Runtime | Node 22+ | `node:sqlite` is built in, so there are no native deps to compile in Docker |
| Server | Hono + `@hono/node-server` | Small, fast, Web-standard `Request`/`Response` |
| LLM | AI SDK v7 (`ai`) + `@ai-sdk/openai`, `anthropic`, `google`, `openai-compatible`, plus an in-repo native Ollama adapter | Covers all four OpenCode Go wire formats and Ollama's own `/api/chat` without another dependency. See `docs/implementation/ollama.md` |
| MCP | `@ai-sdk/mcp` | Streamable HTTP, SSE, stdio clients |
| DB | SQLite via `node:sqlite` | One file, one volume |
| Web | Vite + React 19 + Tailwind v4 | No SSR needed |
| Chat UI | assistant-ui (`@assistant-ui/react`, `@assistant-ui/ai-sdk`), components copied into `src/web/components/assistant-ui/elements/` | Required by the product brief. Copied (shadcn-style) so we can add slots |
| UI primitives | Base UI (`@base-ui/react`), lucide icons, zustand stores | Same primitives the assistant-ui registry uses |
| Math / diagrams | `remark-math` + KaTeX, Mermaid, both lazy-loaded on first use | Chat Markdown renders LaTeX and ```` ```mermaid ```` blocks. See `docs/implementation/code-blocks.md` |
| Generative UI | `generative-frame` (spec mode + sandboxed widgets) | Both renderers, streaming, render reports for repair. See `docs/implementation/generative-ui.md` |
| Files | `unpdf` (PDF), `mammoth` (DOCX) | Pure JS, no native deps |
| Browser worker | Separate `browser` container (`src/browser/`): Playwright Chromium + Scrapling, egress proxy, per-uid firewall | Keeps Chromium and untrusted pages away from app data and secrets. See `docs/implementation/browser-worker.md` |
| Speech | Separate `speech` container (`speech/`): Piper (read aloud) and faster-whisper (speech to text), each in a child process that exits when idle; cloud engines over plain `fetch` | Natural local voices and Whisper without bloating the app; memory only while in use. See `docs/implementation/speech.md` |
| Email | `imapflow` + `nodemailer` + `mailparser`, all pure JS, plus `@xmldom/xmldom` for autoconfig XML | IMAP, SMTP, and MIME are too subtle to hand-roll; these are maintained, have TypeScript types, and need no native build. See `docs/implementation/email.md` |
| Images | Codex CLI, AI SDK image providers (`@ai-sdk/xai`, `black-forest-labs`, `fal`, `replicate`, `togetherai` plus openai/google) | Small packages on the same provider-utils. See `docs/implementation/image-generation.md` |
| Web | `linkedom` + `@mozilla/readability` + `turndown`; SearXNG sidecar for search | Free, no keys. See `docs/implementation/web-search.md` |
| i18n | Own `t()` on `Intl` (`src/web/i18n/`), English catalog only | Typed keys and plurals without a dependency. See `docs/implementation/i18n.md` |
| Theming | Port of T3Code appearance settings (MIT) | Required by the product brief |
| Depth | `theme/depth.css`: lit surfaces, tinted shadows, accent gradients derived from theme tokens | Matches the brand icon. See `docs/implementation/visual-depth.md` |

## Working with subagents

You can delegate to smaller-model subagents (for example Haiku) for specialized, well-bounded tasks: researching one library and writing a doc, porting a file, mechanical refactors, writing tests for a known interface. Give them the exact files, the target path, and the acceptance check. Keep architecture decisions and cross-cutting changes with the main agent, and review subagent output before relying on it.

## Conventions

- TypeScript strict. ESM only.
- Server code never imports from `src/web`. Shared types live in `src/shared`.
- Secrets (provider keys, MCP tokens) and memory content are encrypted at rest with `OKAYCHAT_SECRET` (AES-256-GCM). This protects a copied database file only, not a compromised server, which holds the key. See the threat model in `docs/implementation/memory.md`. Never log secrets.
- Match the surrounding code style. Comments explain why, not what.
- Commits: no co-author lines.

## Non-obvious facts

- assistant-ui puts unknown message metadata keys under `metadata.custom`. Server-side code that reads raw AI SDK messages sees them at the top level. `metadataOf()` and `currentContextTokens()` handle both.
- `useAuiState` selectors must return primitives or stable references, or React re-renders forever.
- The model is per chat. A stored chat uses `threadModels[threadId]` (picked in its composer and PATCHed to `threads.model_ref`, or loaded from the thread list); a new chat uses the in-memory `selectedModel`, cleared for fresh chats and copied to the thread when it is created. Read it in chat components with `useChatModel()` and elsewhere with `getActiveModel(remoteId)`. Never restore the legacy `okaychat:selected-model` local-storage key, which masked account defaults. Resolution is chat choice → active project → account default → first available model. Settings fallback menu items persist `null` to clear overrides (`undefined` disappears from JSON). See `docs/implementation/assistant-ui.md`.
- The composer's Search toggle is an in-memory per-chat override (`state/chat-search.ts`), sent as `config.webSearch` and keyed by thread id, bound to the remote id when a thread is created. It only hides `web_search`; `web_fetch` stays, and the account's `webTools` setting still disables both. On touch devices and below the `sm` breakpoint the reasoning and search controls move into the plus-button menu, which also triggers attachments. "Instant" is the label for `none` reasoning effort.
- The chat request body comes from `AssistantChatTransport`: thread id is `id`, model and effort are `config.modelName` / `config.reasoningEffort` (registered in `ModelContextBridge`).
- models.dev lists embedding, rerank, and speech models with text output and most image models with text+image output. The chat model list drops models whose output is anything but text, and ids/families matching `NON_CHAT_ID` in `catalog/models-dev.ts` (live and custom-provider lists too).
- Ollama is first-class (`format: "ollama"`, provider id `ollama`), not a `custom-*` OpenAI-compatible endpoint. `catalog/ollama.ts` speaks native `/api/version|tags|show|ps|chat|embed|pull|delete`; `ollama-model.ts` is an in-repo `LanguageModelV4` adapter used by `llm.ts` (the installed AI SDK is v7/v4, not V2). `/api/show` is authoritative for context and capabilities; embedding-only models stay out of chat but remain in the management inventory. Refs are `ollama/<name>` and names may contain slashes. The default URL is `http://127.0.0.1:11434`; admins may use private hosts, everyone else's requests go through `publicFetch` for every native endpoint. A shared connection is readable by its audience, but pull/delete require the user's own row; admins manage the shared row from Admin → Providers. No prompt-cache fields are sent (the daemon manages its own cache), and a cancelled pull can keep running in the daemon. Effort from `createModel` becomes native `think` (boolean on/off models, named levels for gpt-oss; `none` only where the daemon accepts false), and every request sends `options.num_ctx` equal to the advertised context so the meter and the daemon's runtime window agree. Cancelling the returned chat stream or a pull reader aborts its own upstream fetch even without a request signal; a pull lock is released after that cleanup, not before. See `docs/implementation/ollama.md`.
- The `chatgpt` provider is the Codex login (`codex_auth`), not a key. `readConnections()` adds it as a virtual connection while the login exists; a `provider_connections` row only stores its on/off switch, and it can never be shared by an admin. `catalog/chatgpt.ts` lists its models from the Codex backend and wraps fetch: bearer token from `codexAccess()` (refreshed in the same per-user queue as CLI runs, because the refresh token rotates), `stream: true`, `store: false`, no `temperature` or `prompt_cache_breakpoint`. See `docs/implementation/codex-chat.md`.
- Shared provider connections and shared MCP servers have an audience (`groups.ts`). No `share_audiences` row means everyone; a row restricts the resource to the users in `share_users` plus members of the groups in `share_groups`. Readers filter with the `audienceIncludes()` SQL condition (bind the user id twice). Deleting the resource must call `clearAudience()`, because provider ids repeat and a stale restriction would apply to a re-added key. A restricted provider does not reach the admin either unless they are in its audience.
- Shared provider keys also have per-audience model policies (`entitlements.ts`, `docs/implementation/entitlements.md`). One policy per target (`everyone`, a user, a group); a missing row means all models, so legacy connections and newly added audience entries default to the old behaviour. Access is the union of matching targets, any `all` wins, and a user's own connection bypasses policies. `listModels()` and `listProviders()` filter and hide a restricted key with no current entitled model; the user Ollama inventory also filters shared model rows and counts; `resolveModel()` and `createModel()` reject with a 403 naming the administrator before any upstream request, and `createModel()` rechecks so an earlier model/connection pair or a fabricated `shared` connection cannot pass. Stored ids missing from the current catalog are ignored at runtime and labelled in the admin dialog; the API accepts only current ids plus an audience's already-stored ones. `setAudience()` prunes removed targets but keeps retained policies; `clearAudience()` and the `shared_connections` foreign key clear them on delete. Admin routes are `GET`/`PUT /admin/providers/:id/entitlements`.
- OpenCode Go ids missing from models.dev inherit the wire format of a sibling in the same family (`qwen3.6-plus` uses Anthropic like `qwen3.8-max`).
- Documents are artifacts with bytes: `content` is the HTML/JSON source and `data`/`size` the built file. `edit_document` with source edits rebuilds; with `ops` it edits the binary and clears the source so a rebuild cannot undo it. Imported attachments are only editable with `ops`.
- Chromium runs only in the browser worker container (`src/browser/`), never in the app. In the container each part is its own user: the job API (`jobs`, holds the token, no browser), one render slot per concurrent job (exits after each job), the fetch server with Scrapling over stdio (`scrape`), and the egress proxy (`egress`); the firewall allows each only the connections in `docs/implementation/browser-worker.md`. `npm run dev` runs all of it in one process (role `all`). It starts on the first job, shares one process across fresh contexts, and closes 60 s after the last one. Renders are offline (only the document and staged files) except HTML/React previews, which may load `FRAME_NETWORK_HOSTS` through the worker's egress proxy. A timed-out or abandoned job has its context closed (browser killed if wedged) before its slot is released. The app talks to it through `browser.ts` with a token it generates into `OKAYCHAT_BROWSER_TOKEN_FILE`; there is no `.env` entry. See `docs/implementation/browser-worker.md`.
- `tsconfig.server.json` includes the DOM lib because `linkedom`/`@xmldom/xmldom` types refer to `Element`/`Document`. Use the xmldom aliases (`XmlElement`, `Document as XmlDocument`) in OOXML code.
- `view_artifact` renders in the browser worker and returns a screenshot to the model. The image is injected once by `prepareStep` as a synthetic user message, never inside the tool result (OpenAI-compatible APIs stringify tool content). Only vision models get the tool, six screenshots per reply, and nothing image-related is persisted. PDF pages come from pdf.js, DOCX from docx-preview, XLSX from the preview JSON.
- DuckDuckGo HTML endpoints return 202 (bot wall) from many servers and Bing serves junk to scrapers. Search goes SearXNG, then Brave HTML, then DuckDuckGo lite.
- Context fill uses the last step's input + output tokens, not the turn total.
- `generate_image` offers every connected image service the account left on. OpenAI/Gemini/xAI/Together reuse the chat provider connection; image-only keys are `image-<service>` provider connections. With several services the tool requires a `service` and tells the model to ask the user first. Generated images may be JPEG/WebP/GIF: `images.mime` is authoritative, the file name stays `<id>.png`. See `docs/implementation/image-generation.md`.
- `threads.updated_at` is last message activity, bumped only by `appendMessage`. `updateThread` (rename, pin, archive, move, title) must not touch it, or the sidebar's date groups jump. See `docs/implementation/assistant-ui.md`.
- Depth (highlights, tinted shadows, accent gradients) comes from `depth-*` utilities in `theme/depth.css`, derived from semantic tokens with `color-mix`. Use them instead of `shadow-*`/`bg-primary` on primitives, and never hardcode colors there or theme switches break. See `docs/implementation/visual-depth.md`.
- Branding uses separate `public/icon.webp` (the lit tile with white dialogue marks) and `public/wordmark.svg` (rounded serif paths). `Brand.tsx` uses a CSS mask for the wordmark, filled by `--app-theme-accent`; the icon and browser icons use `theme/brand.ts` tinting from the source dark accent `#b5c062`, preserving lighting and white marks. Use the shared component instead of plain okaychat text beside the icon. PWA/browser PNGs contain only the icon. See `docs/implementation/appearance.md`.
- Sidebar multi-selection starts from a row's "Select" menu item. State lives in `state/thread-selection.ts` (rows render inside assistant-ui's list); `ThreadListItemGroups` publishes the visible order, used for Shift ranges and Select all, and ids leaving it drop from the selection. Bulk Pin/Move/Archive/Delete go through `aui.threads.item({ id })`, so the runtime list stays in sync. The Library uses the same helpers (`components/ui/selection.tsx`); see `docs/implementation/library.md`.
- Keyboard: every action is a command in `keyboard/commands.ts`, reachable by a configurable shortcut (`user_settings.keyboard`) and by name in the command list. A new button that does something a user may want without a pointer needs a command: `useCommand(id, handler)` where the state lives, or `data-command={id}` (`command` on `TooltipIconButton`) on the control. Never hide a control until hover without a `focus-visible`/`group-focus-visible` counterpart. Defaults use Alt+Shift+letter because Ctrl/⌘+Shift+letter is taken by browsers; `keys.test.ts` fails on a default that clashes. See `docs/implementation/keyboard.md`.
- Sidebar shortcuts are configurable per account (`sidebarItems` in General settings). Search is a global spotlight dialog (Ctrl/Cmd+K), independent of the project filter; selecting a result clears that filter. `/scheduled`, `/projects`, `/library`, and `/plugins` retain the chat sidebar and lazy-load `NavigationPage`; Plugins holds MCP servers and Skills. See `docs/implementation/assistant-ui.md` and `docs/implementation/library.md`.
- Skills are Agent Skills (SKILL.md + optional files), stored per account. The enabled-skills index is injected beside the latest user message, never in the system prefix; `load_skill`/`read_skill_file` fetch bodies on demand. `install_skill`/`create_skill` always require approval, exist only for non-temporary chats with the preference on, and never reach delegates — `turnSkills()` returns a read-only `subTools` pair for them. Every skill-tool execution re-checks the captured preference revision, so switching skills off revokes tools mid-run. Normal skill CRUD does not bump the revision; tools read live tables. Source installs recheck revocation after fetching. Skill sources use pinned public DNS and revalidated redirects, 30 s/20 MB download bounds and bounded ZIP expansion and their content is stored as text — never executed. See `docs/implementation/skills.md`.
- System prompts live in `prompts.ts`, not next to their callers. Read them with `promptText(key, values)`; a new prompt needs a `PromptKey` in `shared/types.ts` and a `DEFS` entry, and then shows up on the admin page. Overrides are server-wide and replace the default text entirely; saving text equal to the default stores no override. Unknown `{name}` tokens stay literal (the artifact prompt contains `{page}`).
- Hono matches routes in registration order: static paths (e.g. `/skills/sources`) must be registered before parameterized ones (`/skills/:id`) or they are shadowed.
- A `never`-returning helper only drives control-flow narrowing as a function *declaration* (or an arrow without defaulted params). `const invalid = (msg, status = 400): never => …` silently fails narrowing under `noUncheckedIndexedAccess`; `skills.ts` declares it as a function for this reason.
- Icon motion is global: `motion/icons.ts` (installed in `main.tsx`) sets `data-icon-motion="hover"|"press"` on lucide icons inside the control being hovered or focused (after a 1 s settle delay) or clicked (immediately), and clears it when the animations finish. Gestures live in `motion/icons.css`, keyed by lucide's `lucide-<name>` class and child order; unknown icons get a generic lift and pop. Spinners are skipped; opt a subtree out with `data-icon-motion-off`. Sidebar selection uses `GlideHighlight` (rows opt in with `data-glide`).
- Reasoning and tool calls render as a T3 Code-style work log (`thread.aui.tsx`): each reasoning block is a one-line `ReasoningRow`, each tool a one-line row, and an adjacent run containing tool calls sits in one group labelled by `workLabel()` ("Searched 3 times and read 2 pages · 41s"). Elapsed time appears only on groups with tool calls, never on plain reasoning. generative-frame renders `read_me`/`preview_widget` as nothing, so `widgetHelperRenders` (`tool-ui.tsx`) gives them rows. Tools whose card must stay visible get a `"tool-call:<name>": []` entry in `messageGroupBy`. Once a reply is `complete`, `foldWork()` moves everything except its outcome into one collapsed log group: the outcome is all parts after the last tool call plus the last card per result (`resultKey()`: artifact id, widget title, spec, each image). A new card tool needs a `resultKey` case. `run_code` cards are work; a finished reply shows its files once in `ReplyFiles` below the text. Artifact versions count turns, not tool calls: `saveVersion` overwrites the version the current turn already saved (`INSERT OR REPLACE`, quota charges net growth), and continuation requests recover the turn's ids with `artifactsInCurrentTurn()`. - Knowledge (`src/server/knowledge/`, `shared/knowledge.ts`): account collections optionally bound to a project, sources with original bytes in `uploads` plus extracted text, deterministic `k_…` chunks (~800-token target, ~12% overlap, heading titles, char offsets that index the exact stored text including CRLF), and normalized float32 vectors. The models.dev catalog is compacted to the fields `RawModel` lists. `GET /threads/:id/messages` splices the stored JSON rather than parsing it.
- DB migrations are append-only SQL or synchronous functions, each wrapped with its own version update in one transaction. `tx()` uses savepoints so multi-skill imports and nested storage helpers roll back atomically.
- "Retry with another model" (`components/chat/retry-model.tsx`) is an in-place sibling, never a branch: `selectModel(ref, threadId)` then `startRun({ parentId: message.parentId })`, whose parent is the user message the assistant reply answered. The model bridge resolves both `config.modelName` and that model’s reasoning effort from the live store when the request is built, so selecting first is enough. Its popover stays mounted on older messages through `ActionBarMorePrimitive.Root`, like `BranchMenu`; it is disabled while `useThreadSync()` holds cached history, running, loading, or with no models.
- Both keyboard palettes read `commandAvailable()` **before** their modal mounts, because an open dialog makes the rest of the page inert; the Ctrl/⌘+K spotlight and Ctrl/⌘+/ list both build rows only from `COMMANDS` (never a second action list), exclude `palette: false` from runnable rows, and exclude `app.search` from the spotlight so it cannot reopen itself. Running a spotlight command closes the dialog first, suppresses its `finalFocus` return, then dispatches on the next task so the command's destination keeps focus.
- Settings deep links go through `lib/settings-link.ts` (`settingsHref`), which returns `/settings/<section>?focus=<anchor>`; `SettingsLayout` reads that query and focuses `#setting-<anchor>` one frame after the lazy section mounts. `SettingsRow` supplies the id and `tabIndex=-1`; do not hand-write settings URLs in components.
- Empty-chat shortcut hints persist as `user_settings.shortcutHintsDismissed` (validated in `settings-schema.ts`). `useData.updateSettings` applies its patch optimistically, so a failed dismissal must restore the previous value or a rejected save looks permanent.

**Dev servers always use HTTPS through Tailscale Serve, with an explicit port.** `npm run dev` / `npm run dev:web` automatically run `tailscale serve --bg --yes --https=5173 http://127.0.0.1:5173`, then start Vite on loopback with a strict port (so the proxy cannot silently target the wrong port). Share `https://<host>.<tailnet>.ts.net:5173`. Tailscale must be running with Serve/HTTPS enabled and permission for the current user to configure Serve. Keep other Serve ports intact; never reset the node’s Serve configuration. Do not bind to `0.0.0.0` or fall back to plain HTTP.

Local dev needs `.env` with `OKAYCHAT_SECRET` (see `.env.example`). Web tools in dev need two helpers, or search fails (Brave 429, DuckDuckGo 202 from this host):

- SearXNG container `okaychat-dev-searxng` on `127.0.0.1:8888` (`OKAYCHAT_SEARXNG_URL`). Command in `.env.example`.
- Scrapling via `scripts/dev-scrapling.sh`, which runs it from the `okaychat-browser:latest` image (`OKAYCHAT_SCRAPLING_COMMAND`, read by the dev browser worker). Build it first: `docker build --target browser -t okaychat-browser:latest .`.

Documents and screenshots in dev use the local browser worker that `npm run dev` starts (Playwright's Chromium from `~/.cache/ms-playwright`). For the hardened container, run `scripts/dev-browser.sh` and set `OKAYCHAT_BROWSER_URL=http://127.0.0.1:8792` in `.env`.

Speech in dev: run `scripts/dev-speech.sh` (container `okaychat-dev-speech` on 127.0.0.1:8793, token in `data/speech-token`) and set `OKAYCHAT_SPEECH_URL=http://127.0.0.1:8793` in `.env`. `test/integration/speech.sh` checks the real worker container.

Code execution in dev: set `OKAYCHAT_SANDBOX_TOKEN` and `OKAYCHAT_SANDBOX_URL=http://127.0.0.1:8790` in `.env`, then run `scripts/dev-sandbox.sh` (container `okaychat-dev-sandbox`). Unlike compose, the dev sandbox container has internet access, but runs still have no network: each gets its own network namespace.

The server reads `.env` only at start. Restart `npm run dev` after editing it.
